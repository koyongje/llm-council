# 의장 답변에 "주요 비판"·"반대 의견" 섹션 추가 — 설계 (소규모 변경)

## 의도
최종 답변 하나만으로는 결론이 어디서 갈리고 어디가 약한지 보이지 않는다. 의장(Stage 3) 답변에
비판적 피드백과 반대 의견을 함께 담아 사용자가 더 많은 통찰을 얻게 한다.

## 접근 방식 (검토한 안)
- **A. 답변 간 이견 (선택)** — Stage 1에서 다수와 다른 결론·근거를 의장이 정리. 프롬프트만 변경, 추가 호출 없음.
- B. 평가자 간 이견 — Stage 2 순위가 갈린 지점. 평가 신뢰도 정보일 뿐 내용상 이견이 아님.
- C. 최종 답변 반박 단계 — 가장 날카롭지만 질문당 API 호출 1회 + 대기 시간 증가.

사용자 선택: **A + 핵심 비판 요약**.

## 설계
- `stage3_synthesize_final`의 의장 프롬프트에 지시 추가: 본문(파일 첨부 시 표 + 메모) 뒤에 두 섹션을 반드시 붙인다.
  - `## 주요 비판` — Stage 2 평가와 Stage 1 단서에서 나온, 최종 결론의 약점·위험·불확실성 핵심 2–5개.
  - `## 반대 의견` — 합의와 다른 결론을 낸 모델(모델명 명시)과 그 근거. Stage 3는 익명화 대상이 아니므로 모델명 표기 가능.
- **반대 의견이 없으면 지어내지 않는다**: "실질적인 반대 의견 없음"이라고 쓴다. (안티 목표: 형식을 채우려고 만든 가짜 이견)
- URL 규칙(`CHAIRMAN_URL_RULE`)과 `⚠️ 미검증` 표시는 두 섹션에도 그대로 적용된다(답변 전체에 적용되므로 코드 변경 없음).
- 스트림·일괄 엔드포인트 모두 `stage3_synthesize_final`을 쓰므로 자동으로 함께 반영된다.
- 프론트엔드 변경 없음: Stage3는 이미 `remarkGfm`으로 마크다운 제목을 렌더링한다.

## 내 판단으로 정한 것 (확인 부탁)
- 후속 질문(자유 형식 답변)에도 두 섹션을 항상 붙이되 짧게 쓴다.
- 섹션 제목은 한국어 고정(`## 주요 비판`, `## 반대 의견`).
- 의장 답변이 다음 턴의 대화 기록에 포함되므로 그만큼 입력 토큰이 늘어난다 — 감수.

## 범위 밖
- Stage 2 프롬프트·순위 파싱 형식 변경 없음.
- 별도 반박 호출, 구조화된 JSON 출력, UI 전용 컴포넌트 없음.

## 검증
- 단위 테스트: 의장 프롬프트에 두 섹션 지시와 "지어내지 말 것" 지시가 파일 유무와 상관없이 포함되는지 확인.
- 실제 출력 품질은 실제 API 호출로만 확인 가능(유료) — 사용자 승인 시 1회 실행.
